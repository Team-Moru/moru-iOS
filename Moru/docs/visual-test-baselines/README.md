# Visual test baselines

`FinalScreenVisualTests` uses the PNGs in `final-screens/` as its approved
Light UI baselines. MORU's supported appearance is iPhone portrait, Korean,
and Light UI, so the suite records Medium and Accessibility 3 variants only.

The tests compare perceptual dHashes with a Hamming-distance limit of 24.
Keeping the PNGs, instead of only their encoded hashes, makes failures
reviewable: the test output points to both the checked-in baseline and the
new image written under `/private/tmp`.

`review-146/` records the approval evidence for issue #146. Each screen keeps
the previous reference and current candidate as side-by-side, overlay,
difference heatmap, and JSON metrics generated by:

```sh
xcrun swift Scripts/figma-visual-compare.swift \
  --reference <approved.png> \
  --candidate <candidate.png> \
  --output-dir <review-directory>
```

The Home, History, Profile, and routine-conflict differences were accepted as
intentional product/copy changes already present on `main`. The onboarding
organizing pair documents an animated-frame false regression. That state uses
the same perceptual comparison as the approved baselines, while static states
continue to require byte-identical repeat captures.
